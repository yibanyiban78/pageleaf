# 页笺 · 本地 Markdown 剪藏

适用于桌面 Chrome 122 或更高版本。无须 Obsidian、Node、页笺账号或本地后台服务；不改动书签或现有笔记库。代码随扩展提供，无远程脚本、统计或遥测。

**[最新版下载](https://github.com/yibanyiban78/pageleaf/releases/latest)** · [安装说明](#下载与安装) · [隐私政策](PRIVACY.md)

## 从网页剪藏到本地编辑

点「页笺」预览并确认保存，再用任意 Markdown 编辑器打开生成的 `.md`。如果你需要一个桌面编辑器，可以试试同作者的 [Markdown Editor](https://github.com/yibanyiban78/markdown-editor)：直接打开磁盘上的笔记，配图与笔记保留在同一归档结构中。两款工具均可单独使用，不需要绑定账号或共用剪藏库。

## 下载与安装

**[下载最新版（GitHub Releases）](https://github.com/yibanyiban78/pageleaf/releases/latest)** · [直接下载 1.2.0 ZIP](https://github.com/yibanyiban78/pageleaf/releases/download/v1.2.0/pageleaf-1.2.0.zip)

页笺免费，目前不在任何扩展商店分发。请只从本仓库的 Release 页面下载。每位用户使用自己的 Chrome 个人资料、剪藏文件夹和可选 AI 服务；没有页笺账号、共享库或遥测。GitHub 附件的下载次数不等于安装人数或活跃人数。

1. 在发布页 **Assets（附件）** 中下载 `pageleaf-1.2.0.zip`，不要选 GitHub 自动生成的 **Source code**。校验和也在同一页。
2. 把 ZIP 完整解压到一个**长期保留、专门放页笺程序**的目录。不要解压到剪藏笔记库；加载成功后不要移动或删除该程序目录。
3. 在桌面 Chrome 地址栏输入 `chrome://extensions`，打开「开发者模式」，点「加载已解压的扩展程序」，选择**直接包含 `manifest.json` 的那层文件夹**。GitHub 的 1.2.0 安装包根目录就是这一层，不用再找 `extension` 子目录。
4. 核对扩展卡片显示「页笺」和 `1.2.0`。固定图标，打开设置，选择你自己的剪藏目录即可开始；AI 服务是可选项。若单位管理的浏览器禁止开发者模式，请联系管理员，不要绕过策略。

### 已安装用户：手动更新，不要先卸载

GitHub 版本**不会由 Chrome 自动更新**。可在仓库的 **Watch → Custom → Releases** 订阅发布通知。

等在途剪藏结束，在原 Chrome 个人资料的扩展详情中核对页笺的 ID 和原加载路径。把新 ZIP 先解压到临时位置，再把**解压出的全部程序文件和子目录**复制到原扩展目录，覆盖同名文件，保持 `manifest.json` 仍在原位置；旧开发包加载的是 `extension/`，就覆盖到那个目录。不要覆盖笔记库或套一层版本号目录。回到原卡片点「重新加载」⟳，核对版本更新且 ID 不变。如果不确定原路径，先停下，不要卸载后重装。

## 已有 Key？升级后不用重填

在**同一 Chrome 个人资料、同一扩展 ID** 内升级，不要先卸载。第一次打开新版设置时，如果发现旧版已保存的 API Key，按提示设置并确认一个至少 12 个字符的本地口令。页笺校验新密文能解回原 Key 后才替换旧记录；在这之前，原 Key 不丢失，也不会用于模型请求。旧磁盘备份不受此次迁移影响。

以后 Chrome 重启或扩展更新后，加密记录仍在，输入本地口令即可继续使用原 Key。锁定时不发摘要请求，原文仍可保存。口令不是模型 Key；页笺不保存或上传口令，没有云端找回。如果忘记口令，只能明确移除本地服务设置、用自己留存或重新签发的 Key 配置；已存笔记不受影响。不同资料、不同扩展 ID 或卸载后的全新安装不会自动取得旧凭据。

## 历史开发包：从 1.0.0 原地升级至 1.1.0

**不要先移除旧扩展。** 打开 `chrome://extensions` → 页笺「详细信息」，确认 1.0.0 已加载的扩展目录。把新 ZIP 解压到临时位置，将新版 `extension` **里面的全部文件和子目录**复制并覆盖到原来的扩展目录（不要再套一层 `extension`）。回扩展管理页点击页笺卡片的「重新加载」⟳，确认页上显示 1.1.0。保留原加载路径才能沿用原扩展 ID、剪藏目录和 AI 设置；不要覆盖自己的笔记目录。已归档的笔记、图片和索引不会被批量修改。

## 首次设置

1. 确认已按上面的「下载与安装」加载页笺，并打开的是你自己要用的 Chrome 个人资料。
2. 在 Chrome 拼图菜单中把「页笺」固定到工具栏。安装、剪藏和出错时都不自动打开设置。需要设置时，在预览里主动点「去设置」，或右击页笺图标 →「选项」。
3. 点「选择文件夹」，在系统窗口选择**专用剪藏根目录**并允许编辑。Chrome 可能拒绝盘符根目录、系统目录、下载根目录等敏感位置，选其中的普通子文件夹即可。若重开浏览器后要求授权，回到设置点「重新授权」，再重新剪藏；不会改存到下载目录。
4. 在「中文摘要」填写指定服务的 **API 地址、模型名称**。若服务需要 API Key，再输入 Key 和本地保护口令，点「保存 AI 设置」并允许访问该服务。无 Key 的服务不需要设置口令。支持 OpenAI 兼容的 Chat Completions：例如 `https://api.example.com/v1` 或完整的 `https://api.example.com/v1/chat/completions`。模型用服务商的确切 ID，不是显示昵称。远端须为 HTTPS，回环地址允许 HTTP。**保存设置不产生模型调用**。只支持返回非流式 `choices[0].message.content` 文本的服务，不直接支持其他专有协议。
5. **HTTP 图片只写成普通原图链接**，不自动请求或尝试升级到 HTTPS；打开笔记也不会因图片语法自动加载它。HTTPS 图片可尝试下载，「允许跨站保存 HTTPS 图片」只向 Chrome 申请 HTTPS 跨站访问，可以不授权或随时撤销。可直接读取的内嵌位图仍可保存在本地。图像不可用不阻止保存笔记。

## 日常使用

| 在哪里点击工具栏图标 | 会得到什么 |
|---|---|
| 普通文章页 | 标题、原文链接、可识别作者、中文摘要和保留段落层次的正文。正文配图下载到这篇笔记对应的本地资源文件夹。|
| YouTube 视频页 | 视频和频道信息、封面、基于字幕的中文摘要、原视频简介和带跳转时间戳的字幕全文，都在这份笔记里。只取一条可用字幕轨；不下载媒体、不做语音识别。|
| 已选中网页的一段或多段连续内容 | 只保存选区及其中的图，带上页面出处；不调用 AI。在视频页上选中文字也是摘录。|

点页笺只在图标下打开预览。先看标题、作者、片段、图数或视频字幕状态和预计文件位置；同名时实际文件名会加编号。预览不写笔记/索引、不下载图片、不调用字幕接口或模型。若字幕全文尚未读到，显示「待检查」，不是宣称有或没有。点「取消」、按 Esc、点到弹窗外和直接关闭都不会保存。

**只有点「确认保存」才会开始。** 文章/选段按预览快照归档；YouTube 如有需要，会在确认后从同一视频补取可用字幕。可以继续阅读，后台临时任务标签不抢焦点、完成后自动关闭。不要提前关闭任务页。工具栏徽标 `…` 表示进行中，`✓` 表示已保存，`!` 表示部分成功，`×` 表示未完成。悬停图标或看设置页「最近一次剪藏」可查看原因和文件位置。无需为同一任务再点一次。

```
我的剪藏/
├── 剪藏索引.md
└── 2026-11-26/
    ├── 频道名 - 视频标题.md
    ├── 文章标题.md
    ├── 文章标题 - 摘录.md
    └── assets/
        ├── m-71a24bb64af8c120/cover.jpg
        └── m-08fd61a2bf33452a/01.png
```

日期按**点击剪藏时电脑的本地日期**。再次剪同名内容保留独立副本，不覆盖旧文件。索引按日期倒序；索引和本地图片均用相对链接。可以整体移动归档目录；若还想往新位置写，需重新选择目录。纯文本编辑器能看 Markdown 源文，支持 Markdown 的阅读器能渲染图片。

## 数据边界

完整说明见[页笺隐私政策](PRIVACY.md)，包括何时联网、数据由谁接收，以及如何移除本地服务设置。

- 只在主动剪藏时读取当前网页，不后台巡览。扩展不读取输入框里的密码、表单或浏览器历史。跨站图片授权是 Chrome 的广域站点权限，不是系统目录授权；目录读写另行由你指定。
- 整篇文章只把正文文本发给你配置的 AI 接口；视频只发送字幕文本。长文本可能分段调用再合并，**可能产生多次计费**（每次剪藏最多 32 个请求，无自动重试）。超过 16 万字符不假装已概括全文，仍可保存原文。选区、无字幕视频不调用模型，图片不发给模型。涉及不宜外发的内容时，可剪选段，或使用自己可信的本机服务。
- 使用 1.2.0 新保存或已迁移的 Key 时，扩展的 IndexedDB 保存由本地口令保护的密文；解锁后的 Key 仅在该资料的扩展会话内存中使用。页笺不持久保存口令，不把 Key 或口令写入笔记、索引或 Chrome Sync。切换接口不会把旧 Key 转给新服务。需要时在设置里锁定或移除服务；如需让已签发的 Key 失效，请到服务商处撤销。
- Markdown 和图片是普通文件，没有加密；所在文件夹是否会被其他软件同步取决于你的电脑设置。卸载扩展不删除已经写到磁盘的归档。

## 笔记里的图片打不开怎么办？

请将 Markdown 笔记和同一日期目录内的 `assets` 一起保留，在支持本地相对图片的 Markdown 阅读器中，**直接打开磁盘上的原笔记**。只上传一份 MD 到在线预览、粘贴源文或单独移动笔记时，阅读器可能没有原文件夹位置或读取配图的权限。

1.1.0 的新笔记使用不含中文、空格或百分号编码的短资源目录，可避免部分阅读器对旧链接解码不一致。保存前会确认图片确实能解码；WebP/AVIF 视频封面会转成真正的 JPEG，并非只改后缀。旧版已生成的文件不会被改写。若只是一份旧笔记坏图，可以用新版重新剪藏（生成新文件，不覆盖原笔记），或者在你的本地编辑器中重新插入该笔记配套的封面，保存为相对链接。

## 哪些情况会降级

- YouTube 有字幕不等于当前页面一定能读取。插件优先尝试当前页提供的字幕轨，其次读取页面原生文字稿；必要时临时展开该视频的简介和「内容转文字」面板，用户未操作时尽量恢复原状态。如果未取得文字稿，保留链接、简介和可用封面，在笔记里明确标记无可用字幕、未生成摘要，不拿简介代替。可在 YouTube 自己的页面打开「显示文字稿」再剪一次。登录限制、直播、界面实验、分页、无字幕或站点改版可能影响结果；插件不绕过访问限制。
- 遇到登录图片、禁止跨域、跳转的图床、超时或过大图片（单张上限 12 MiB），保留能访问的原图链接并标注「未保存到本地」。支持 PNG、JPEG、GIF、WebP、AVIF 位图；SVG、画布、视频帧不作为本地活动内容保存。
- AI 未配置、网络/额度问题、模型不兼容：原文和可用图片照存，摘要部分标记失败。Chrome 内置页、商店、PDF 查看器、跨域嵌套文档不是本版支持的正文来源。复杂文章识别不准时，可改用选区剪藏。
- 笔记成功、索引失败会分开提示。笔记仍可直接打开，不用反复剪藏。检查根目录是否可写、索引是否被其他软件占用；已有索引须为 UTF-8。可在自动索引区外加自己的文字，不要删改成对的 `pageleaf:index:v1` 注释。

## 开发与验证

源码用户可在桌面 Chrome 的开发者模式直接加载 `extension/`，不需构建。安装 Node 24+ 后运行 `npm ci`、`npm test`；使用兼容的桌面 Chrome 运行 `node tests/browser.mjs` 做独立浏览器集成检查。使用 `python tools/package_store.py` 可复建扩展 ZIP（脚本沿用历史产物名 `pageleaf-cws-<版本>.zip`）；上传到 GitHub Release 时附件命名为 `pageleaf-<版本>.zip`，内容不变。ZIP 根目录直接包含 `manifest.json`，只打包运行文件与 MIT 许可证。测试、剪藏数据、密钥和提交材料均不打进扩展 ZIP。重复构建相同版本应产生相同哈希，不覆盖不同内容的同名包。普通使用者无须执行这些命令。

Windows 桌面可在构建候选 ZIP 后运行 `node tests/store-profiles.mjs`：使用两个新建的临时 Chrome 个人资料、两个测试目录与模拟服务，验证配置、笔记和索引独立。测试输出只保存在本地，不提交 Git。

版本变化见 [CHANGELOG](CHANGELOG.md)，源码采用 [MIT 许可证](LICENSE)。维护时在分支上开发，合并前运行模块和浏览器检查；修改发布内容须同步扩展版本、项目版本和锁文件。`vX.Y.Z-rc.N` 是候选标签；确认发布到 GitHub 时以 `vX.Y.Z` 建立正式 Release，附上扩展 ZIP、SHA-256 和安装说明，不重写已有标签。GitHub 正式版不代表已上架任何商店。
